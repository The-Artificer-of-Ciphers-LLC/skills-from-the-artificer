### 3D. The Deterministic Review Pass (invoked by §3A.7 and §3B.7)
**[BLOCKING]** *No LLM in this path — local linters, the repo's own checks and CodeGraph. Its findings are evidence, not opinion, and they land in §8 as such.*

1. **The repo's own deterministic checks** on the PR checkout: `npm run lint` (ESLint, including `local/no-source-grep`) and the type check. Run the test suite only through the repo's sanctioned runner, never local `node --test`. Report each check by name with its result.
2. **Cross-module drift with CodeGraph.** For every symbol the diff renames, removes or changes the signature of, run `codegraph callers <old name>` on the PR checkout. A caller that still uses the old name or old signature is **removed-symbol-still-referenced (Critical)** or caller signature drift. Also check that every new import resolves (`codegraph node <imported symbol>`).
3. **Optional: `memtrace review --diff`** on `<scratchpad>/pr-<PR>.diff`, where the `memtrace` CLI is installed. It runs AST detectors and the YAML rule pack locally and contacts neither GitHub nor Memtrace's cloud. Check its flags with `memtrace review --help` before the first run; do not guess them. If the CLI is missing or errors, say so in the review and rely on steps 1–2; never report a check that could not run as clean.
4. *(Retired: the per-file Memtrace diff tools — `detect_changes`, `find_cross_module_issues`, `find_code_review_issues`, `find_yaml_rule_matches`, `find_ast_review_issues` — and `review_github_pr`. Together they were the biggest quota cost in this directive. If step 3 is unavailable, `/security-review` (§3A.8 / §3B.5) carries the rule-pack classes: CSPRNG misuse, SQL string concatenation, disabled TLS verification, unsafe deserialization, sync I/O inside async.)*
