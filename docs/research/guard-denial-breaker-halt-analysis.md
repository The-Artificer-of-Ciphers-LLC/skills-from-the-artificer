# Why the guard denial breaker halts Claude, and how to make it self-correct

Date: 2026-10-03. Repo state: commit 8c7d31a (branch claude/circuit-breaker-hooks-14720f).
Repo cites are `file:line` under `claude-guards/hooks/` unless prefixed; line numbers are at 8c7d31a.
Docs cites are the Claude Code hooks reference, https://code.claude.com/docs/en/hooks (raw-markdown line numbers from a fetch on 2026-10-03; section names given).
Note: no docs/ or research/ folder existed; `docs/research/` was chosen because memtrace-first-guard.cjs already cites `docs/research/codegraph-fallback-equivalents.md` (that file is not in the repo).

## 1. Short answer

- No hook in this repo uses `continue:false` or `stopReason` (grep for `continue.?:\s*false|stopReason` over claude-guards, gsd-core-hooks, artifact-gates, cost-routing: zero hits). So the harness never halts Claude. Every halt is Claude obeying TEXT the hooks feed it.
- Three text sources cause the stop:
  1. Individual guards tell Claude to stop: memtrace-first-guard.cjs:1281 ("SAY SO TO THE USER and stop"), measure-dont-infer-guard.cjs:61 and :776-777 ("SAY SO TO THE USER and stop"), :803 ("Do not reword this again - say so to the user instead").
  2. The breaker's backstop (guard-denial-breaker.cjs:272-282) denies EVERY tool call after 5 restarts per human turn with "Stop now. Tool calls are disabled until the user replies." The only exempt call is a Write to `.gsd/phase/<x>/HALT.md` (:273-275).
  3. The "special code" the user remembers: the human escape tokens advertised in denials. `GSD_HUMAN_OVERRIDE=1` (gsd-core-hooks/hooks/gsd-test-single-flight-guard.sh:38, :283, :330; also pre-pr-gate.sh:311, gsd-bench-pin-guard.sh:66 and others), `GSD_MERGE_GATE_OVERRIDE=1` (gsd-merge-authority-guard.cjs:76), `GSD_PHASE_GATE_OVERRIDE=1` (gsd-phase-gate.cjs:158), `ARTIFACT_GATE_OVERRIDE=1` (artifact-gates/SKILL.md:169), and env kill switches `GSD_MEMTRACE_GUARD_OFF=1` (memtrace-first-guard.cjs:1300), `GSD_MEASURE_GUARD_OFF=1` (measure-dont-infer-guard.cjs:777), `GSD_GUARD_BREAKER_OFF=1` (guard-denial-breaker.cjs:56,226), `GSD_WORKTREE_GUARD_OFF=1` (worktree-guard.cjs:134). They are generated by nothing: the user must type/export them. Each denial labels them "Human-only escape, never for the agent", so Claude's only remaining move is to stop and ask. There is no generated one-time code anywhere.
- The breaker also makes the problem worse (section 3): it trips on guard denial text that Claude is already correctly obeying, and it burns a legitimate tool call each time.

### How the breaker works (guard-denial-breaker.cjs)
- Stateless; reads the transcript tail (:107-121, 8 MB cap :66), finds the last real human message (:138-158, :244-248).
- A "trip" is a tool_result that is an error or looks like a hook/classifier denial AND contains a T1 phrase: "do not rephrase", "do not route around", "circumvention", "safety bypass", "don't pursue the same outcome", "do not work around", "denied by the claude code auto mode classifier" (:74-82, :171-191). Subagent hand-backs are never trips (:174-178, commit fa75e37 / #27).
- After a trip, the NEXT tool call of any kind is denied once with `GUARD-BREAKER RESTART: ... Do not report this to the user and do not wait for them...` (:288-295). That text is the ack (sentinel :70-71, :201-207). Later calls pass until a new trip (:285).
- Backstop: `acks >= MAX_RESTARTS_PER_TURN (5)` -> deny everything except HALT.md write, text ends with "Stop now ... until the user replies" (:69, :272-282). A new human message resets (:263).
- History: 115b112 (original: deny everything until human types - "made the agent stop and ask the human", per header :12-14), f97efbc / #26 (changed to one-shot restart + backstop), fa75e37 / #27 (hand-backs never trip).
- Tests: guard-denial-breaker.test.sh (49 cases per commit message of f97efbc/fa75e37; backstop text assertion at :177, restart text :169-173).
- Evidence it fires in practice: ~/.claude/logs/guard-denial-breaker.jsonl shows, in one session on 2026-10-03, two `restart` entries then four consecutive `backstop` entries (tool `Write`), all quoting measure-dont-infer-guard's "DO NOT REPHRASE" text. So within roughly 30 s a single guard denial chain produced the hard stop.

## 3. Root cause

1. The guard denials contain T1 phrases by design (memtrace-first-guard.cjs:1278-1281 "DO NOT REPHRASE ... circumvention"; measure-dont-infer-guard.cjs:57-61 ANTI_CIRCUMVENTION). So EVERY denial from these guards is a breaker trip, including when Claude does exactly what the denial prescribes. The trip has no notion of whether Claude subsequently complied.
2. A trip denies the next tool call regardless of what it is (:272-295). If Claude's next call is the compliant one (e.g. `find_symbol`), that good call is thrown away. That produces another tool_result, and a measure-dont-infer repeat-denial (:787-806, which itself says "say so to the user") produces another trip. Five of those = backstop.
3. The restart text has no concrete next step; it says "use the compliant path the guard prescribes" and "If no compliant path exists ... pick a different step" (:292-294). When Claude cannot see one, it stops.
4. The backstop is a count of interrupts per human turn, not a detector of repetition. A long, productive autonomous run that hits a guard five times is treated the same as a loop. It then forbids all tools (:277-281), which forces a stop and waits for a human message.
5. Individual guards instruct "say so to the user and stop" (see section 1). Claude follows that.
6. All override tokens are human-only by design, so there is no agent-usable way out.

Which Claude Code semantic causes the halt: none of the hook-level halts. It is PreToolUse `deny` (non-halting, per docs below) plus instruction text that tells the model to stop, plus a backstop that denies all tools.

## 4. Claude Code hook semantics (primary source)

All from https://code.claude.com/docs/en/hooks.
- PreToolUse `permissionDecision: "deny"`: "For `"deny"`, shown to Claude" (section "PreToolUse decision control", table row for `permissionDecisionReason`, raw line 1804). The tool call is blocked; the conversation continues and Claude reads the reason. (A first-pass summarizer claimed the reason is user-only; the raw page contradicts it - trust line 1804. The repo's own transcripts agree: the breaker reads deny text out of tool_results, guard-denial-breaker.cjs:44-46.)
- Exit code 2 per event (section "Exit code 2 behavior per event", lines 852-861): PreToolUse "Blocks the tool call"; Stop "Prevents Claude from stopping, continues the conversation"; SubagentStop "Prevents the subagent from stopping". Exit 2 beats a JSON allow (line 798).
- `continue: false` (section "JSON output", line 927): "Claude stops processing entirely after the hook runs. Takes precedence over any event-specific decision fields". `stopReason` (line 928) is shown to the user. This is the real hard halt; repo does not use it.
- Stop / SubagentStop `decision:"block"` + `reason` (Decision control table, line 1019; line 2027: reason "shown to Claude"): forces Claude to continue. Stop also accepts `hookSpecificOutput.additionalContext` for non-error feedback that keeps the conversation going (line 1019, line 2620).
- Loop protection: Stop input has `stop_hook_active`, "true when Claude Code is already continuing as a result of a stop hook"; Claude Code also applies an "8-consecutive-continuation cap", override with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` (line 2541). SubagentStop input also has `stop_hook_active` (line 2390; the first-pass summary wrongly said it does not).
- `additionalContext` (section "Add context for Claude", lines 976-1001): string wrapped in a system reminder and inserted where the hook fired; capped at 10,000 chars (line 913). On PreToolUse it is delivered next to the tool result; line 825 lists `additionalContext` as honored alongside `permissionDecision`.
- Top-level `decision`/`reason` for PreToolUse is deprecated; use `hookSpecificOutput.permissionDecision` (line 1837). The repo already does.

## 5. Recommended design

Principle: a denial is a redirect with the exact replacement action; stop only on provable repetition with no progress.

### A. Rewrite denial text (all guards)
Files: memtrace-first-guard.cjs denyOutput (:1276-1307); measure-dont-infer-guard.cjs ANTI_CIRCUMVENTION (:57-61), main deny (:776-784), denyRepeat (:787-806); gsd-test-single-flight-guard.sh (:283, :330) and sibling gsd-core-hooks guards' "Human-only escape" trailer.
- Delete "SAY SO TO THE USER and stop" and "do not wait"-type text. Replace with: the exact next tool call to make (concrete args built from the denied input, e.g. for a Read of file F lines a-b: `get_source_window({file_path:<abs F>, start_line:a, end_line:b})`), then "continue the task; do not report this denial".
- Keep the anti-circumvention intent but phrase it without the T1 strings, or (preferred, see B) stop using strings as the trip signal.
- Move the human escape hint out of the deny reason (or reduce to one line). It is noise that invites the model to ask the user.
- Optionally add `additionalContext` in the same PreToolUse JSON with the remedy so it is delivered as a system reminder (docs line 976-984).

### B. Replace phrase-based trips with repetition detection in the breaker
File: guard-denial-breaker.cjs. Functions: `tripText` (:171), `findT1Phrase` (:160), main (:225-296).
- Each guard emits a machine marker in its reason (e.g. `GUARD-DENY id=<guard> sig=<hash(tool, normalized input)>`); the breaker keys on the marker, not T1 prose. (If markers are not wanted, derive sig from the tool_use that preceded the denied tool_result.)
- Count denials with identical (guard id, sig) or identical normalized tool_input since the last human message, or since the last successful (non-denied) tool call of a different kind (= progress). Escalate only when the same sig repeats N times in a row (suggest N=3) with no intervening progress.
- Below the threshold: the breaker must ALLOW (no collateral denial of the next call). The guard's own corrective text already did the redirect. Optionally return allow plus `additionalContext` reminding the compliant path.
- At threshold, first escalation: deny that exact repeated call once with a concrete "you are repeating X; the only compliant action is Y; do Y now" text.
- Second repeat of the same sig after that: genuine loop. Only now halt. Prefer a Stop-hook style ending, or deny with a handback instruction. If a hard halt is wanted use `continue:false` + `stopReason` explicitly rather than denying all tools indefinitely.

### C. Replace the all-tools backstop
Remove the `acks >= MAX_RESTARTS_PER_TURN` hard deny (:69, :272-282) and the HALT.md exemption (:273-275). Replace with the per-signature loop rule in B. Do not count unrelated denials toward a global total; a long run with many different, correctly-handled denials must continue.

### D. Stop-side safety net (keeps Claude working)
run-incomplete-guard.cjs (Stop, :434) and pr-claim-verifier.cjs (:233) already use `decision:"block"`. Add `stop_hook_active` handling to run-incomplete-guard (it has none: grep over the file returns zero hits), plus a persisted block counter so it cannot loop past a small bound; the harness 8-continuation cap (docs line 2541) is the outer limit. Optionally use `additionalContext` (docs line 2620) for the non-error "keep going" case.

### E. Exit-2 guards
measure-dont-infer-guard.cjs and no-defer-guard.js emit stderr + exit 2 (valid, blocks only that call per docs line 854). Keep, but fix stderr text per A.

### F. Tests to add/update
- guard-denial-breaker.test.sh: update the "restart text" cases (:169-173) and "backstop" case (:177); add: (1) a single guard denial followed by a compliant call -> ALLOW, no breaker deny; (2) 5 different-sig denials in one turn -> still ALLOW; (3) same sig 3 times consecutively -> first escalation deny with concrete remedy; (4) same sig after escalation -> halt; (5) a successful different tool call between repeats resets the counter; (6) human message resets; (7) subagent hand-back still never trips (keep #27 cases); (8) deny output contains no "ask the user"/"wait" instruction.
- memtrace-first-guard.test.sh, measure-dont-infer-guard.test.sh: assert the deny reason contains no "say so to the user"/"and stop" text and contains the concrete replacement call.
- gsd-test-single-flight-guard.test.sh: assert the deny includes the poll/launch-on-free-bench remedy and no human-escape-only dead end.
